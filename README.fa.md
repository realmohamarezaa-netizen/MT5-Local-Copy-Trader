# Trading Copier — کپی‌تریدر محلی چندحسابی متاتریدر ۵ (ویندوز ۶۴ بیتی)

نرم‌افزار **کاملاً محلی** برای کپی معاملات بین چند ترمینال MetaTrader 5 روی
ویندوز ۱۰/۱۱ نسخه ۶۴ بیتی. بدون سرور ابری، بدون اکسپرت (EA)، بدون فایل MQL5،
بدون سرویس کپی خارجی. تمام پردازش، دیتابیس و رابط کاربری روی سیستم خودتان اجرا می‌شود.

- اتصال به **تعداد نامحدود** ترمینال MT5 نصب‌شده روی همان کامپیوتر
- انتخاب یک حساب به‌عنوان **مستر** و هر تعداد حساب به‌عنوان **استیو**
- کپی معاملات بازشده دستی یا الگوریتمی مستر به همه استیوهای فعال در حد میلی‌ثانیه
- انتقال تغییرات SL/TP، بستن بخشی، بستن کامل، تغییر حجم و چرخه کامل سفارش‌های معلق
- داشبورد زنده: وضعیت حساب‌ها، اکوییتی/مارجین، پوزیشن‌ها، رویدادهای کپی و تأخیرها

## معماری

| لایه | تکنولوژی |
|---|---|
| رابط کاربری | Python 3.11 + PySide6 (Qt6)، تم تیره، فارسی/انگلیسی + RTL |
| دسترسی به MT5 | پکیج رسمی `MetaTrader5` پایتون (از بیرون ترمینال، بدون EA) |
| ایزوله‌سازی | یک **پردازش Worker مستقل برای هر ترمینال** (اتصال مستقل، عدم تأثیر خرابی روی بقیه) |
| ارتباط داخلی | Named Pipes ویندوز (`multiprocessing.connection`، پیام JSON) |
| موتور معاملاتی | تشخیص رویداد (Diff پوزیشن‌ها + History Deals افزایشی با پنجره هم‌پوشان)، صف رویداد یکتا، ارسال موازی به استیوها، Reconciliation دوره‌ای |
| ذخیره‌سازی | SQLite با حالت WAL در `%LOCALAPPDATA%\TradingCopier` |
| اسرار | رمزها فقط با DPAPI ویندوز رمزنگاری می‌شوند (بدون متن ساده) |
| بسته‌بندی | PyInstaller + نصب‌کننده Inno Setup + ساخت خودکار در GitHub Actions |

## دریافت نسخه نصب ویندوز

فایل نصب به‌صورت خودکار توسط GitHub Actions ساخته می‌شود:

1. در همین مخزن به بخش **Releases** بروید.
2. فایل **`TradingCopierSetup_x64.zip`** را دانلود کنید (داخل آن فایل نصب
   کلاسیک `TradingCopierSetup_x64.exe` قرار دارد).
3. فایل ZIP را باز کنید و Setup را اجرا کنید. نصب در سطح کاربر (بدون نیاز
   به Administrator)، شورتکات دسکتاپ و Start Menu و Uninstaller کامل دارد.

برای ساخت محلی روی ویندوز: Python 3.11 x64 و
[Inno Setup 6](https://jrsoftware.org/isinfo.php) را نصب کنید و
`build\build_windows.bat` را اجرا کنید.

## چک‌لیست اجرای اول (حتماً ابتدا روی حساب دمو!)

1. در هر ترمینال MT5 دکمه **Algo Trading** را فعال کنید.
2. برنامه را اجرا کنید → **افزودن ترمینال** → جست‌وجوی خودکار یا انتخاب
   دستی `terminal64.exe`.
3. مطمئن شوید هر ترمینال به حسابش لاگین است (برنامه از Session خود ترمینال
   استفاده می‌کند؛ فیلد رمز اختیاری است و فقط با DPAPI ذخیره می‌شود).
4. روی ردیف ترمینال موردنظر **تبدیل به مستر** را بزنید؛ بقیه استیو می‌مانند.
5. تنظیمات هر استیو (روش حجم، سقف‌های ریسک، نگاشت نمادها) را از
   **تنظیمات** انجام دهید.
6. **شروع کپی** را بزنید. به سؤال همگام‌سازی پاسخ «خیر» بدهید تا فقط
   معاملات جدید کپی شوند (پیش‌فرض توصیه‌شده).
7. ابتدا روی **حساب دمو** تست کنید. استفاده از حساب واقعی با تصمیم خودتان است.

## تست‌ها

```bash
pip install pytest
pytest tests -q        # ۳۳ تست؛ همه Mock هستند و هرگز به MT5 واقعی سفارش نمی‌زنند
```

بنچمارک پایپ‌لاین محلی:

```bash
python scripts/benchmark.py
```

نتیجه اندازه‌گیری (بدون دخالت بروکر): تشخیص رویداد مستر، میانه **≈۰٫۲ میلی‌ثانیه**
و صدک ۹۵ **≈۰٫۴ میلی‌ثانیه**؛ سریال‌سازی JSON اسنپ‌شات ۳۰ پوزیشنی ≈۰٫۰۸ میلی‌ثانیه
(~۷ کیلوبایت). تأخیر انتها-به-انتها در اجرای واقعی توسط
`event_actions.latency_total_us` ثبت و در داشبورد نمایش داده می‌شود.

## اصول ایمنی پیاده‌سازی‌شده

- هر رویداد دقیقاً **یک‌بار** پردازش می‌شود (کلید یکتا از شناسه‌های واقعی Deal/Order/Position)
- Timeout یا نتیجه نامشخص ⇒ `RECONCILIATION_REQUIRED`؛ **هرگز** ارسال مجدد کورکورانه
- معاملات دستی استیوها هرگز دست‌کاری نمی‌شوند (عملیات فقط روی نگاشت‌های موتور کپی)
- وضعیت نامشخص حساب ⇒ عدم ارسال سفارش جدید (Fail Safe)
- بسته‌شدن معامله مستر ⇒ بستن معامله استیو (Reconciliation دوره‌ای هم تضمین می‌کند)
- PAUSE جلوی معاملات جدید را می‌گیرد ولی مدیریت معاملات قبلی ادامه دارد
- EMERGENCY STOP بلافاصله ارسال دستورات را قطع و وضعیت عملیات نیمه‌تمام را نمایش می‌دهد
- CLOSE COPIED POSITIONS فقط پوزیشن‌های متعلق به موتور کپی را — با تأیید کاربر — می‌بندد

## محدودیت‌های شفاف

- در این مخزن تایید شده: ۳۳ تست خودکار (تشخیص رویداد، Dedup، محاسبات حجم،
  نگاشت نماد، جریان کپی، رفت‌وبرگشت IPC) و ساخت EXE/Setup در CI ویندوز.
  **تست زنده چندترمینالی باید روی سیستم واقعی ویندوز با ترمینال‌های دمو
  انجام شود** — برای هر ترمینال `scripts/validate_connection.py` را اجرا کنید
  (چک‌لیست فاز ۱ در مستندات).
- کپی از مستر Netting به استیو Hedging مجاز است ولی معنای بستن بخشی متفاوت
  است؛ قبل از ترکیب انواع حساب، مستندات را بخوانید.
- استفاده از یک `terminal64.exe` واحد برای دو پوشه دیتا (`/portable`) از یک
  نمونه برنامه امکان‌پذیر نیست (محدودیت API متاتریدر: هر مسیر نصب، یک اتصال).
